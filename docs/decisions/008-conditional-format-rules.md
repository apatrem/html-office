# Readable conditional formatting rules

Status: core and highlight viewport rendering/authoring merged, 20 October 2026. Data bar rendering/worker summaries are in PR #36; bar authoring is under verification.

Update, 22 October 2026: colours are charte tokens rather than hex values ([ADR-012](012-data-formatting-vocabulary.md) §10). Highlights use `style: {fill?, color?, bold?, italic?}`; data bars use `positive` and `negative` tokens.

Store optional `conditionalFormats` as an ordered array of explicit stable-ID sheet/range rules. At most 100 rules are accepted. Overlapping ranges are allowed: the first matching highlight wins as a whole style, and the first applicable data bar wins independently. These layers can coexist without changing a cell's value or semantic role. Rule creation, replacement, removal and reordering are metadata commands; header history preserves the order and structural edits shift/shrink ranges or retain an inactive `#REF!` tombstone.

Highlights use typed predicates (`eq`, `ne`, `gt`, `gte`, `lt`, `lte`, inclusive `between`/`notBetween`, case-sensitive `contains`, `isBlank`, `isError`). Comparisons do not coerce text/numbers/dates. Ordered predicates require one numeric/date type. An absent/style-only cell is blank; empty text is distinct. A formula without a saved result is unresolved, not blank. Errors match `isError` or an explicit typed error comparison, and do not satisfy ordinary numeric/text predicates. Highlight style accepts only six-digit hex background/text colours and an optional bold boolean; arbitrary CSS and formula expressions are not part of the contract.

Data bars accept typed numbers/dates, including saved formula results. Text, booleans, blanks, errors and missing results do not produce bars. Automatic scaling scans populated cells in the explicit target range and extends the observed bounds to include zero. Fixed finite bounds must include zero and have a nonzero span; values outside them are clipped visually. Positive-only ranges start at zero; negative-only ranges end at zero; mixed signs share one zero axis. A constant positive/negative range fills its corresponding side, while an all-zero range has a zero-width bar. Normalizing before subtraction avoids overflowing finite extremes such as ±1e308. Original values and formula precision stay unchanged.

Scale summaries and presentations are derived. Do not expand Excel-sized blank rectangles or attach per-cell persisted flags/styles. The pure summary accepts sparse canonical overrides so a future worker can analyse committed values even while its recovery document contains pending edits. Rendering will use the bounded visible viewport; worker integration must suppress obsolete summaries and retain existing recovery/save guarantees. Formula-derived highlights require a verified current snapshot. Before startup/recovery verification or when an external edit invalidates the saved snapshot, suppress formula highlights and describe their unavailability; raw input highlights remain available. Repaint after verification succeeds. A failed attempted edit preserves the previous canonical values, verified snapshot and appearance until the new calculation commits. Saved stale results must continue to be identified as stale rather than becoming current through formatting.

This feature is a small explicit rule system, not another formula evaluator or an assertion of exhaustive Excel conditional-format compatibility.
