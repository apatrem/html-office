# Formula compatibility fixes in the single IronCalc engine

Status: implementation candidate under T12 verification, 20 October 2026. This does not approve a release or relax the conformance/performance gates.

The first frozen aggregation/logic fixtures exposed incorrect results in the pinned upstream 0.9.0 calculation core: plural criteria functions accepted unequal range shapes; criteria errors became empty matches; single-criterion sum/average ranges were not aligned from their top-left reference; AND/OR skipped later errors. Expectations are independent small calculations derived from the reference documentation, not copied from engine output. They are not a claim of validation against every Excel behaviour.

Keep IronCalc as the sole formula evaluator. Carry a small explicit source patch, with regression tests, on the pinned upstream revision. Rebuild the same narrow typed binding and publish a distinct immutable engine version only after independent review, deterministic two-path executable rebuilds, dependency/licence auditing and both HTML distribution tests. Preserve the patch alongside the source revision and artifact hashes. Existing saved engines remain identifiable; their cached results become stale under the new version rather than being presented as recalculated values.

This fixes the agreed function contract within the existing engine. Do not rewrite formula text to hide discrepancies, add a browser/Python evaluator, substitute numeric caches, or quietly remove promised functions. Further conformance failures must be fixed and tested or raised as an explicit product decision. Shared formatting/reader code keeps the same standard-mode size ceiling and lazy-download behaviour.

Reference rules: [SUMIF range alignment](https://support.microsoft.com/en-us/excel/functions/sumif-function), [SUMIFS matching shapes](https://support.microsoft.com/en-us/excel/functions/sumifs-function), [COUNTIFS matching shapes](https://support.microsoft.com/en-gb/excel/functions/countifs-function), [AVERAGEIFS matching shapes](https://support.microsoft.com/en-us/excel/functions/averageifs-function), [error propagation](https://support.microsoft.com/en-us/excel/detect-formula-errors-in-excel), and Sestoft's primary research description of Excel's evaluation distinction in [Spreadsheet Technology, §7.8](https://en.itu.dk/-/media/EN/Research/About-ITU-Research/Technical-Reports/2011/ITUTR2011142pdf.pdf#page=157). The separate single-criterion and plural-function shape rules must remain covered together to prevent a strict-shape fix from breaking valid SUMIF/AVERAGEIF inputs.
